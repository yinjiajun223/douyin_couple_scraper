# 本地调试

## 首次准备

需要 Node.js 22.12+、npm、Docker Desktop 和本机 Chrome。项目不会连接正式 RDS；本地数据库固定监听 `127.0.0.1:33306`。

```powershell
Set-Location 'C:\Users\ic\Desktop\douyin_couple_scraper'
npm install
if (-not (Test-Path .env.local)) { Copy-Item .env.local.example .env.local }
npm run dev:setup
```

`dev:setup` 会启动持久化 MySQL 8、执行迁移和种子，并创建 `.env.local` 中的首位管理员。它会拒绝远程数据库地址，重复运行不会重复创建相同管理员。

本地配置请从 `.env.local.example` 复制，`.env.example` 是服务器配置模板。如果已有 `.env.local`，先检查其中 `NODE_ENV=development`、数据库地址为 `127.0.0.1:33306`，以及 `BOOTSTRAP_ADMIN_*` 已填写，避免覆盖自己填写的配置。

`dev:setup` 和 `dev:local` 均以 `.env.local` 中显式填写的值为准，会覆盖当前终端的同名环境变量；未在文件中配置的变量仍从终端继承。

## 启动与登录

```powershell
npm run dev:local
```

启动完成后访问：

- 管理后台：`http://127.0.0.1:5173`
- API readiness：`http://127.0.0.1:3000/health/ready`
- Windows 采集控制页：`http://127.0.0.1:43127`

默认登录邮箱为 `admin@local.test`，密码读取 `.env.local` 的 `BOOTSTRAP_ADMIN_PASSWORD`。前后端源码会在保存后重新编译或刷新；按 `Ctrl+C` 停止应用。

如果之前启动过旧版本，先在旧终端按 `Ctrl+C`，再执行 `npm run dev:local`，刷新两个页面。不要同时运行 `run.ps1` 或分发包启动器，否则会争用采集助手端口。

## 从空工作台走完一次流程

1. 登录管理后台，进入“采集设备”，点“生成配对码”，再点“打开本机助手”。
2. 在采集助手填写设备名称和配对码，点“完成配对”。看到“已连接团队”才算成功。
3. 创建一个画像，例如“校园日常”。画像是独立浏览器登录目录，不会读取你平时 Chrome 的账号。创建多个画像时，先选择要使用的那个。
4. 点“打开抖音登录”，在打开的可见 Chrome 中人工登录、处理验证码、确认推荐圈层。此时没有开始自动采集。
5. 回到管理后台 →“筛选任务”→“新建筛选任务”，调整规则后保存。初次测试可把“最多浏览作品”设为 5，限制试运行范围。
6. 在任务卡片点“创建运行”。任务保存筛选配置；每次运行使用一份独立规则快照。**创建运行不会自动打开或操作抖音。**
7. 回到采集助手，刷新任务，确认画像正确。低可信度页面默认永不导致暂停；如需保护性停机，可主动改为“连续 N 条低可信度后暂停”。策略在运行中也能即时保存。随后在对应运行点“人工开始”；重启助手不会自动继续。
8. 在管理后台“运行监控”看进度，在“达人库”打开候选，检查作品、粉丝数、观察时间和私有截图。达人库支持按日期筛选和分组；管理员还可按运营成员查看。
9. 在达人详情填写理由并保存人工结论，再从成员下拉框选择负责人、保存联系资料，最后把合作阶段改成“待联系”。后续沟通记录采用追加方式保存。

年龄、素人属性和内容适配需要人工判断。当前采集器读取公开页面已加载的作品，无法保证穷尽近 15 天全部作品；没有找到爆款但作品窗口不完整时标为“未知”，不会当作确定不符合。

## OSS

默认 `OSS_READINESS_PROBE=false`，适合先调账号、任务、运行和人工复核。要测试真实截图直传时，将 `.env.local` 的 OSS 配置替换成专用测试 bucket/RAM 凭据并设置 `OSS_READINESS_PROBE=true`。不要使用生产 bucket 的永久高权限凭据。

注意：`OSS_READINESS_PROBE=false` 仅跳过启动探测，**不是关闭截图上传，也不是提供假 OSS**。使用占位配置时，遇到需保存证据的候选会在上传阶段暂停；已入库候选仍可查看，本机保留待同步批次和截图。请补好测试 OSS 配置、重启服务，再继续同一次运行，不要删除 `.local/collector-data`。

## 常见卡点

- 提示 `NODE_ENV=production`：确认使用 `.env.local.example`，并把 `.env.local` 中的 `NODE_ENV` 改为 `development`。不需要修改系统全局环境变量。
- Docker / MySQL 连接失败：先打开 Docker Desktop，等待启动完成，再执行 `npm run dev:setup`。
- 采集助手打不开：确认 `npm run dev:local` 终端还在运行，查看带 collector 前缀的日志，不要重复启动多个助手。
- 配对失败：配对码只可使用一次，过期或用过后在后台重新生成。撤销设备后旧授权不能继续使用。
- 登录、验证码、页面结构异常：登录失效、验证码和异常页面会立即暂停，必须在可见浏览器中人工处理。普通低可信度作者按本地策略跳过或在连续达到次数后暂停，且始终不会把该条数据写入共享库。
- 同步失败：批次和截图保存在本机，先修复网络、设备授权或 OSS，再点“继续”。有待同步证据时不能切换画像、重新配对或直接终止，避免丢失关联。
- 列表没变化：点击“刷新数据”。旧版登录会话若一直提示权限或提交失败，可退出后重新登录。

## 自动化验证与真实试运行的区别

`npm test` 检查离线逻辑，`npm run test:e2e` 检查页面交互。`npm run test:mysql` 会启动独立的临时 MySQL（33307 端口），验证数据库/API，并执行浏览器流程：登录、配对、建任务、人工开始、断网重试、证据失败后恢复、人工复核与合作跟进。测试结束仅清理隔离测试库，不删除 33306 的开发数据库。

该流程测试使用真实本地 API/MySQL，但抖音页面与 OSS 是受控测试替身，未验证真实抖音页面准确性。真实试运行需你在本机人工登录并配置测试 OSS；先小范围运行、抽样核对，不应据自动化测试结果直接认定生产可用。

## 停止数据库

```powershell
npm run dev:stop
```

该命令停止 MySQL 容器但保留开发数据卷，下次执行 `npm run dev:setup` 会继续使用原数据。若要删除数据卷，先确认不再需要本地数据，再手动执行带 `--volumes` 的 Compose down。
