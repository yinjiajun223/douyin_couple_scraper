# 运营使用手册

## 1. 人工养号与采集边界

每个推荐圈层使用一个独立的本地浏览器画像。运营人员在可见的抖音页面中自行浏览，并可按日常方式手动点“不感兴趣”来调整推荐流；这是人工行为，不属于采集任务。采集助手不会替你点赞、关注、评论、私信、转发或点击“不感兴趣”，服务器也不能远程启动浏览器。

Cookie、验证码和登录状态只保存在当前 Windows 用户的独立画像中。不要复制画像目录或 DPAPI 令牌给同事；需要换电脑时由管理员撤销旧设备并重新配对。

## 2. 新建筛选任务

1. 登录后台，进入“筛选任务”，填写任务名称和希望进入的推荐圈层说明。
2. 核对硬条件。默认值为粉丝 0–5000、近 15 天至少一条作品达到 10000 赞。
3. 配置人工复核项。素人属性、内容标签与推广适配由人工判断，人工结论是最终业务判断。
4. 配置作品数、时长、候选数等停止条件，保存任务。
5. 创建一次运行。运行保存当时的规则快照，之后修改任务只影响下一次运行。

数据缺失显示为 `unknown/未知`，不按 0 计算。不要仅凭 `pass` 自动联系博主。

## 3. 配对并开始本地采集

1. 请管理员在“采集设备”生成一次性配对码。
2. 源码本地调试按 `docs/local-development.md` 执行 `npm run dev:setup`、`npm run dev:local`；正式分发包按包内说明配置 `.env` 后双击 `start-collector.cmd`。不要同时启动两个助手。
3. 打开 `http://127.0.0.1:43127`，输入设备名称与配对码，完成配对后创建或选择独立画像。
4. 点“打开抖音登录”，人工完成登录或验证码，确认推荐圈层。在管理后台的任务卡片点“创建运行”，回到本地助手刷新任务。
5. “低可信度页面处理”默认是“永不因此暂停”，适合夜间无人值守；也可主动改为连续多少条后暂停。运行过程中可以即时修改并保存，无需先暂停任务。解析阈值始终是 0.75，不会因该设置降低。然后观察低速滚动、主页核验和同步进度。截图直接上传私有 OSS，不经过 API 主机；不会上传完整视频。后台无法远程开始浏览，重启助手后也必须人工继续。

低解析可信度页面会被跳过并只在本机记录，不会进入共享库或 OSS；一次可信解析会把连续失败数清零。达到配置的连续次数时才暂停，选择“永不因此暂停”后可持续采集。验证码、登录失效、异常页面或平台限制不受该配置影响，仍会立即保存进度并暂停；先在可见浏览器中人工处理，再从本地控制页继续。

## 4. 复核候选与合作跟进

1. 在“达人库”按发现日期找到候选，先核对最新粉丝数、观察时间、命中作品链接和规则快照。运营只会看到自己采集或明确分配给自己的达人；管理员可切换运营成员查看。
2. 查看历史观察与任务来源，确认数据是否过期；私有截图每次打开都使用短期地址。
3. 提交“通过 / 不符合 / 待定”及理由。人工结论是业务最终判断；同事已修改时页面会提示版本冲突，应刷新后重做判断。
4. 从成员下拉框选择负责人并保存联系方式、报价和下一步。通过后将阶段推进为“待联系、已联系、沟通中、已合作”或“不合作”，追加沟通备注。

候选可跨任务复用，但每个任务的筛选与合作状态互相独立。服务端支持授权 CSV 导出，当前页面尚无导出入口；接口只允许授权业务字段，不包含会话、设备令牌或 OSS 永久凭据。

## 5. 日常异常处理

- “采集暂停”：查看本地提示。若因连续低可信度暂停，可检查最近缺失字段后调整次数或选择“永不因此暂停”；若是验证码、登录失效或异常页面，必须人工处理后再继续。
- “网络失败”：持久队列会重试；连续失败后暂停，修复后继续原运行。截图上传失败也会保留本机证据；不要删除 `COLLECTOR_DATA_DIR`。
- “需要升级”：暂停运行并按 `docs/collector-windows.md` 换版本，保留旧版本用于回退。
- “素材打不开”：记录候选、运行和素材 ID，请管理员检查 OSS；不要把 bucket 改成公开。
- “数据已被同事更新”：刷新详情后重新提交，不要覆盖同事的新版本。

## 6. 非开发同事验收记录

由未参与开发的运营同事按本手册完成：受邀登录、新建任务、设备配对、人工启动/暂停/继续、查看证据、提交复核、推进到待联系。记录验收人、日期、任务/运行 ID、遇到的问题和结论；未实际走通前不得把 OpenSpec 的同事验收项标记完成。
