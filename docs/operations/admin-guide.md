# 管理员使用手册

## 1. 首位管理员与成员

首次迁移和种子完成后，在服务器容器中运行 `npm run bootstrap-admin -w @douyin/domain` 所对应的发布命令，根据提示提供工作区、邮箱、显示名和强密码。命令受数据库锁保护且只允许成功创建一次首位管理员。

后续成员只通过“成员与邀请”加入，没有公开注册。邀请有有效期且只能使用一次。角色边界：

- 管理员：成员、邀请、设备、模板、审计和全部运营操作。
- 运营人员：任务、运行、复核与合作跟进，不能管理系统密钥。
- 只读成员：查看授权业务数据，不能修改。

成员离职或账号异常时立即停用账号并撤销全部会话；在审计记录中确认动作已留痕。

## 2. 设备生命周期

在“采集设备”生成短期一次性配对码，交给指定同事当面或通过受控渠道输入。设备令牌只在配对时显示一次，服务端只保存哈希，本机由 Windows DPAPI 保护。

设备丢失或换人时先撤销；怀疑令牌泄露时执行轮换并重新配对。撤销后旧令牌不能继续查看运行或提交批次。服务器永远不能代替运营同事点击“人工开始”。

## 3. 安全检查

- 每月复核成员、角色、活跃会话和已配对设备。
- 每周查看审计中的账户、规则、设备、复核、合作和导出动作。
- RDS 只允许服务器出口 IP `/32`，业务账号与迁移账号分离并强制 TLS。
- OSS bucket 保持 private，RAM 权限限定 bucket/prefix；只签发短期 PUT/GET。
- 对外仅开放 80/443；不要开放 API、worker、MySQL 或容器管理端口。
- 日志和导出中不得出现 Cookie、Authorization、设备令牌、密码或 OSS key。

## 4. 管理交接

交接时只移交凭据所在的密码管理器条目和操作文档，不复制浏览器画像。至少两名管理员掌握部署回滚与账户停用流程；每次权限或密钥变更记录日期、执行人、原因和审计事件 ID。
