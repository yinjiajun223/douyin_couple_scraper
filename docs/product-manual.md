# 抖音达人采集运营平台产品手册

本手册面向系统管理员、运营人员和只读成员，说明从登录、设备配对、任务创建、采集、复核到合作跟进的完整流程。开发、部署和故障恢复请使用 README 中对应的技术文档。

## 1. 产品定位

平台用于把分散在运营电脑上的达人发现工作，整理为可追溯的团队流程：

1. 管理员邀请成员并授权采集设备。
2. 运营人员配置筛选任务并创建运行。
3. 运营人员在自己的 Windows 或 macOS 电脑上人工登录抖音、选择推荐圈层并明确开始采集。
4. 采集助手记录公开页面中的达人和作品证据，将结构化数据同步到服务器，将截图直传私有 OSS。
5. 团队在达人库中进行人工复核、分配负责人和记录合作进展。

平台不是无人值守账号机器人。它不会自动点赞、关注、评论、私信、转发或点击“不感兴趣”，也不能从服务器远程启动运营电脑上的浏览器。

## 2. 角色与权限

### 管理员

可以管理成员、邀请、角色、设备、筛选模板和审计记录，也可以执行全部运营操作。管理员负责生产配置和账号安全，但不应在日常工作中直接修改数据库业务数据。

### 运营人员

可以创建筛选任务和运行、使用已授权采集设备、复核候选、分配负责人以及推进合作阶段。不能查看或管理系统密钥。

### 只读成员

可以查看被授权的任务和候选，不能更改任务、复核或系统设置。

页面入口会随角色隐藏或禁用。若某位成员看不到管理菜单，应先由管理员检查其角色，而不是直接修改数据库。

## 3. 登录与首页

1. 使用管理员创建或邀请的账号登录管理后台；系统不提供公开注册。
2. 登录后首先进入“今日工作”，查看运行、待复核候选和合作进度概览。
3. 页面提示“网络连接失败或会话已过期”时，先刷新一次；仍失败则退出并重新登录。
4. 不要共享账号。成员离职或电脑丢失时，管理员应停用账号、撤销会话并撤销对应设备。

## 4. 本机采集助手

### 4.1 安装要求

- Windows 10/11。
- 已安装 Google Chrome。
- 能访问团队管理后台。
- 从管理员处取得经过校验的正式 ZIP。

正式包已包含 Node 和非秘密连接配置，用户不需要安装 Node、npm、Python 或编译工具。macOS 通用包同时包含 Apple Silicon 和 Intel 运行时，启动时会自动选择。

### 4.2 首次启动

1. 将 ZIP 完整解压到固定目录，不要直接在压缩包内运行。
2. 双击 `start-collector.cmd`，保持弹出的控制台窗口开启。
3. 本机控制服务就绪后，浏览器会打开 `http://127.0.0.1:43127`。该地址只代表本机助手，不是公网网站。
4. 若页面打不开，确认控制台仍在运行，并检查窗口中保留的错误信息或是否已有另一个助手占用 43127 端口。

Windows SmartScreen 拦截时，应先核对管理员提供的 SHA256。只有文件校验一致，才可以解除下载文件阻止；不要对来源不明的 ZIP 绕过系统保护。

### 4.3 设备配对

1. 管理员在管理后台“采集设备”生成一次性配对码。
2. 用户在本机助手填写可识别的设备名称和配对码。
3. 页面显示“已连接团队”才算成功。

配对码有效期短且只能使用一次。设备令牌由当前 Windows 用户的 DPAPI 加密，不能复制给其他电脑或其他 Windows 用户。

macOS 的流程相同，但应双击 `start-collector.command`，设备令牌保存在当前用户的 Keychain。首次启动可能出现 Gatekeeper 或钥匙串提示；先核对 SHA256，只允许已知来源的包，不要关闭系统安全保护。详细步骤见 `docs/collector-macos.md`。

### 4.4 创建抖音画像

1. 为一个推荐圈层创建一个独立画像，例如“校园日常”或“美妆测评”。
2. 选择画像后点击“打开抖音登录”。
3. 在出现的可见 Chrome 中人工登录、扫码或处理验证码。
4. 人工浏览并确认推荐内容符合目标圈层后，再开始任务。

画像不会读取日常 Chrome 的用户目录。不要复制画像目录给同事；换电脑时应重新配对并重新登录。

## 5. 筛选任务

进入“筛选任务”并点击“新建筛选任务”。

### 硬筛条件

- 粉丝下限和上限。
- 作品观察窗口天数。
- 窗口内作品点赞门槛。

默认示例是粉丝 0–5000、观察 15 天、至少一条作品达到 10000 赞。页面缺失的数据保持“未知”，不会按 0 计算。

### 人工项和停止条件

- 最多浏览作品。
- 最长运行分钟。
- 目标候选数。
- 可选人工复核说明。

首次联调建议使用很小的停止条件，例如最多浏览 3–5 个作品、最长运行 2–5 分钟。任务保存后，点击“创建运行”。每次运行都会冻结当时的规则；之后修改任务不会改变旧运行的判断依据。

### 编辑、复制与归档

任务卡片提供“编辑”“复制”“归档”“创建运行”四个入口：

- 编辑：表单用该任务当前的粉丝范围、观察窗口、点赞门槛和停止条件预填，保存后卡片版本号 +1，并提示“每次运行开始时都会冻结独立快照，本次修改只影响新的运行”。若提示“该任务已被他人修改，请刷新后重试”，说明同事刚保存过，页面会刷新到最新条件，需要重新填写后再保存，系统不做自动合并。
- 复制：以现有任务为底稿新建一个，需要填写不少于 2 个字的新名称。
- 归档：归档后卡片标记为“已归档”，不能再创建运行，只保留“复制”入口；历史运行与已入库候选不受影响。任务归档当前无法在网页恢复，确认文案也是这样写的，不要指望“先归档再说”。

### 从模板新建（管理员）

管理员在“筛选模板”维护可复用的规则组合，支持新建、编辑和归档；归档后的模板不再出现在新建任务的下拉里，已引用它的任务不受影响。新建任务时可以在“从模板开始（可选）”选择模板，由服务端展开模板规则并记录来源模板；不选模板就手动填写条件。运营成员看不到模板下拉（模板接口只允许管理员），手动填写不受影响。

## 6. 开始和控制采集

1. 在管理后台创建运行。
2. 回到本机助手并点击“刷新任务”。
3. 确认当前抖音画像正确。
4. 点击对应运行的“人工开始”。

只有这一步会开始浏览。后台创建运行、自动刷新、服务重启或助手重启都不会自动开始。

运行期间可以暂停、继续或终止。关闭助手、切换画像或重新配对前，应先等待待同步队列和证据上传完成。

### 低可信度处理

解析阈值固定为 0.75。低可信度页面不会被猜测或写入共享达人库：

- “永不因此暂停”：跳过低可信度页面并继续。
- “连续 N 条后暂停”：达到设定次数后保存进度并暂停。

登录失效、验证码、异常页面或平台限制不受该策略影响，仍会立即暂停。处理完成后从本机助手继续原运行。

## 7. 运行监控

“运行监控”显示：

- 当前状态和领取设备。
- 已浏览作品数。
- 已核验作者数。
- 已发现候选数。
- 停止原因和最新诊断。

运行达到作品数、时长或候选数限制时会自动完成。若浏览器仍显示页面，不代表运行仍在采集，应以本机助手和管理后台状态为准。

### 判定依据

选中某次运行后，“本次运行观察到的达人”面板列出该运行核验过的每一位达人，**包括没有入库的**。每位达人显示昵称、粉丝数、观察时间、抖音主页链接，以及每条硬筛规则（“粉丝范围”“近期爆款作品”）的结论“通过 / 不通过 / 未知”与对应阈值和作品证据；右侧给出总体结论，左侧标注“已入库 · 待复核”或“未入库 · 不进入复核队列”。面板标题旁显示“共 N 位 · 已入库 M 位”。

结论不是采集当时写死的快照，而是由采集到的事实与该运行保存的规则快照重新推导，因此之后修改任务规则不会改变历史运行的判定依据。运营人员问“某位达人为什么没进达人库”时，先在这个面板看结论，不要直接往数据库补候选行。

## 8. 达人库与人工复核

### 8.1 入库闸门

只有全部硬筛规则都判“通过”的达人才会进入达人库。硬筛结论为“不通过”或“未知”的达人不会创建候选行，也不会进入复核队列；采集助手同样不会为他们截图上传。

这些达人并没有丢失：达人与作品观察记录仍完整保存在不可变的事实账本中，结论和判定依据可以在“运行监控”的“本次运行观察到的达人”面板查看（见 7 节）。

闸门放在硬筛而不是人工复核，是为了控制成本。此前只要硬筛通过就建候选并上传截图，而人工复核后真正留下的很少，证据存储和复核队列被大量不会合作的达人占据。数据缺失仍然显示为 `unknown/未知`，不按 0 计算，也不会被当成“通过”。

### 8.2 分区

达人库按合作阶段分为五个分区，另加一个跨阶段的“全部”，全部在服务端过滤：

| 分区 | 包含的合作阶段 |
| --- | --- |
| 全部 | 待复核、不符合、待联系、已联系、沟通中、已合作、不合作 |
| 待复核 | 待复核 |
| 待联系 | 待联系 |
| 跟进中 | 已联系、沟通中 |
| 已合作 | 已合作 |
| 不合适 | 不符合、不合作 |

“全部”承接工作台的“我负责的”卡片，该计数不按阶段过滤。

原来的“证据不足”分区已取消：硬筛结论不再是分区轴，未通过硬筛的达人根本不会有候选行，该分区必然为空。要追查某位达人为什么没入库，请去“运行监控”的判定依据面板，不要在达人库里找。

### 8.3 复核

在“达人库”按日期、分区或运营成员筛选候选。打开候选后重点核对：

- 最新昵称、粉丝数和观察时间。
- 抖音主页及命中作品链接。
- 点赞数、发布时间和采集时间。
- 规则快照、硬筛结论和证据。
- 历史观察和来源运行。
- 私有截图（打开详情即自动加载，不需要逐张点击）。

提交“人工通过、不符合或待定”。理由是可选项，收在“补充理由（可选）”里，留空也能保存。结论会自动推进合作阶段，不需要再手动改一次：

- 待复核 + 人工通过 → 自动进入“待联系”。
- 待复核 + 不符合 → 自动进入“不合适”。
- 待复核 + 待定 → 阶段保持“待复核”。
- 已不在“待复核”的候选：复核结论照常记录并留痕，但阶段不变，避免把已进入跟进的达人退回起点。

每次成功提交只递增一次候选版本，并留下 `manual_reviewed` 与（发生推进时）`pipeline_status_changed` 两条事件。多人同时编辑时，系统可能提示版本冲突；刷新后基于最新数据重新判断，不要覆盖同事的修改。如果提示“当前阶段不允许直接改到这个状态”，说明目标阶段与当前阶段不相邻，刷新后改选相邻阶段即可。

截图在打开详情时自动通过短期地址加载；加载失败的格子会显示“点击重试”。素材打不开时，记录候选、运行和素材 ID 交给管理员排查，不要把 OSS bucket 改成公开。

### 8.4 批量复核与批量归档

列表每行前有勾选框，顶部操作栏提供“选择本页全部”“已选 N 条”“批量通过复核”“批量归档”“清空选择”。

- 一次最多 100 条；超过上限时按钮禁用并提示分批提交。
- 只提交实际勾选的达人，服务端不会按当前筛选条件展开，因此“全选”只等于选中当前页面已加载出来的达人。
- “批量通过复核”等价于逐条提交“人工通过”：处于“待复核”的达人自动进入“待联系”，已不在“待复核”的达人只记录结论、阶段不变。
- 提交期间整条操作栏禁用，不做乐观更新。结果逐条回报，部分失败会归并成一句话，例如“已复核通过 4 条，1 条未处理：已被同事修改 1 条”；失败的那几条没有任何改动，刷新后重新勾选再提交即可。
- 切换分区、切换归档视图或修改筛选条件时，勾选会自动清空或收敛到当前列表，避免把看不见的达人一起提交。
- “已归档”视图不提供批量入口，恢复是逐条决定的。

### 8.5 标签

达人详情的“标签”区可以添加和移除标签：输入标签名后回车是“加一个标签”，点“保存标签”才写入。一位达人最多 20 个标签，标签名最长 100 字；全团队共用同一套标签名，同一工作区内同名标签只有一个。移除某个标签只解除这位达人的关联，不影响其他达人，也不会删除标签本身。保存标签不会递增候选版本，因此不会打断同事正在填写的复核或跟进表单；每次变更都会留下 `tags_changed` 事件与审计记录。

达人库筛选栏的“标签”输入框用于按标签检索：填一个或多个标签名（逗号分隔）后回车生效，出现“清除标签筛选：…”按钮说明筛选正在生效。多个标签是“同时具备”的关系。

### 8.6 归档与恢复：移除达人的唯一方式

平台不提供物理删除候选的入口，**移除一位达人的唯一方式是归档**：

- 列表勾选后点“批量归档”，或在详情页点“归档该达人”，在确认条里可以填写可选的归档原因。
- 归档后这位达人离开达人库、分区与工作台待办统计，也不再出现在 CSV 导出里；采集事实（观察记录、作品证据、规则结论）与私有截图全部保留，不可变账本不会被改写。
- 达人库顶部的“在用列表 / 已归档”开关切到“已归档”即可查看，每行有“恢复”按钮；详情页对应“恢复到在用列表”。恢复后它按当前合作阶段回到在用列表。
- 已归档达人仍属于本工作区的数据：新一轮采集再次命中同一个人时会照常更新观察与运行引用，但不会自动取消归档，需要人工恢复。
- 采集事实字段（粉丝数、观察时间、命中作品等）始终不可编辑，归档也不改变这一点。

## 9. 分配与合作跟进

复核面板默认只保留“复核结论”和“合作阶段”两个表单，方便快速过队列。负责人、联系方式、报价、下一步和沟通备注收在“联系资料与沟通记录（跟进阶段再填）”折叠区里，阶段变更的“说明”同样是可选项。

候选通过复核后已自动处于“待联系”，可以继续：

1. 选择负责人。
2. 保存授权范围内的联系方式、报价和下一步计划。
3. 将阶段推进为“已联系、沟通中、已合作”或“不合作”。
4. 追加沟通备注。

同一达人可以出现在不同任务中，但每个任务的筛选结论、负责人和合作状态互相独立。

## 10. 成员与设备管理

### 邀请成员

管理员在“成员与邀请”创建邀请，并通过受控渠道交给指定成员。邀请有有效期且只能使用一次。

“待处理邀请”列出尚未使用且未过期的邀请（邮箱、角色、发出与过期时间、发出者），任意一条都可以点“撤销邀请”并确认；撤销后链接立即失效，对方再用会看到“邀请已被撤销”。已接受、已撤销或已过期的邀请不会出现在列表里，列表与接口响应都不包含令牌本身。

### 成员生命周期

- 停用：账号级操作，立即撤销该成员的全部登录会话与其名下所有采集设备；已入库的候选与证据不受影响。停用是账户级而不是工作区级，只影响本工作区的身份与设备。
- 启用：只把账号状态改回可用，**不会恢复设备**。被停用期间撤销的设备保持“已撤销”，成员必须在本机重新配对后才能继续同步。
- 改角色：在管理员、运营、只读之间切换，保存后立即生效，对方不需要重新登录；把管理员降为其他角色需要二次确认。
- 护栏：不能停用当前登录的自己；工作区必须保留至少一名启用状态的管理员，因此最后一名管理员既不能停用也不能降级。界面对这两种情况直接禁用按钮并说明原因；并发操作触发护栏时，服务端也会拒绝并把原因显示在列表旁边。
- 万一护栏把所有管理员都挡在外面（例如唯一管理员账号被停用或密码遗失），由具备服务器访问权限的人按 `docs/operations/admin-guide.md` 的救援步骤重建首位管理员。
- 被停用的成员不会出现在“运营成员”筛选和“负责人”下拉里，避免把达人分配给无法登录的账号。

### 管理设备

- 每台电脑使用独立配对码和设备名称。
- 电脑丢失、换人或授权异常时立即撤销设备。
- 已撤销设备默认隐藏，点“显示已撤销 (N)”展开；展开后是只读历史，显示撤销时间，不提供恢复、改名或删除入口。设备被采集观察记录引用，因此无法删除。
- 不复制 `data`、浏览器画像或 `device-token.dpapi`。
- 一位用户升级助手时，新旧版本应共享同一个版本外 `data` 目录；确认新版正常前保留旧版。

## 11. 审计记录

审计页用于追踪成员、规则、设备、复核、合作和导出等关键动作。异常事件调查时优先使用时间、操作者、动作类型和对象 ID 关联，不要直接改数据库掩盖问题。

## 12. 数据查看

日常业务数据应在管理后台查看。管理员可以使用 DMS 做只读核对，但 DMS 是数据库运维工具，不是产品操作入口。

- 表目录为空时先刷新元数据，或使用 `SHOW FULL TABLES FROM douyin_ops` 核对。
- 查询必须带合理的 `LIMIT`。
- 不直接修改 `users`、`sessions`、设备令牌、审计和不可变观察表。
- 不执行未经评审的 `UPDATE`、`DELETE`、`DROP` 或手工结构变更。

## 13. 常见问题

### 如何进入本机助手控制页

每位运营人员都需要先在自己的 Windows 或 macOS 电脑上启动助手。助手通常会自动打开控制页；如果没有自动打开，请在当前电脑的浏览器手动访问 `http://127.0.0.1:43127`。这个地址只代表当前电脑上的助手，不是公网网站，公网服务器也不能代替本机 Chrome。

### 本机助手显示 `fetch failed`

检查正式包中的后台地址、电脑网络、代理/Fake-IP、服务器可达性和 TLS 证书。禁止通过关闭证书验证解决。

### 页面显示“网络连接失败或会话已过期”

刷新一次；仍失败则重新登录。若所有用户同时出现，管理员检查 gateway、API 和 `/health/ready`。

### 运行没有任务

确认管理后台已经“创建运行”，设备仍被授权，然后在本机助手点击“刷新任务”。

### 运行暂停

查看本机原因。验证码、登录失效和异常页面必须人工处理；连续低可信度可在本机调整策略后继续。

### 同步或截图上传失败

不要删除本机数据目录。修复网络、设备授权或 OSS 后继续原运行，持久队列会重试。

### macOS 能否使用

macOS 版本已经使用 Keychain 保存令牌，并提供同时兼容 Apple Silicon/Intel 的通用 Node 运行时和 `.command` 启动器。管理员应使用同一个包分别完成两类真机冒烟和真实小范围试运行。当前团队内测包不是 Apple 公证的 `.app`，首次打开时需要先核对 SHA256，再通过 Finder 的 Control + 点击“打开”。Windows ZIP 不能在 Mac 上使用。

## 14. 安全与隐私清单

- 不共享账号、Cookie、验证码、设备令牌或浏览器画像。
- 不把数据库密码、OSS Secret 或私钥粘贴到聊天、日志和工单。
- 不把私有 OSS 改为公开。
- 不关闭 RDS 或应用 TLS 证书验证。
- 不让采集器执行点赞、关注、评论、私信或其他账号互动。
- 不删除尚有待同步批次或证据的本机数据目录。
- 管理员定期复核成员、活跃会话、设备和审计记录。

## 15. 上线验收

正式交付前至少由一名非开发运营人员完成：

1. 登录或接受邀请。
2. 启动与电脑系统及架构匹配的助手并完成设备配对。
3. 创建、选择并登录独立抖音画像。
4. 新建小范围任务并创建运行。
5. 人工开始、暂停、继续并等待任务完成。
6. 在运行监控核对计数和停止原因。
7. 在达人库查看主页、作品、截图和规则证据。
8. 提交人工复核、分配负责人并推进合作阶段。
9. 对若干候选执行批量复核、打标签、按标签筛选、归档与恢复。
10. 编辑一个筛选任务并确认旧运行的规则快照未变；新建并归档一个模板。
11. 停用并重新启用一名成员，确认其设备保持已撤销、需要在本机重新配对。
12. 验证审计记录和权限边界。

记录验收人、日期、任务/运行 ID、问题和结论。未走通真实流程前，不应仅凭自动化测试宣布生产验收完成。
