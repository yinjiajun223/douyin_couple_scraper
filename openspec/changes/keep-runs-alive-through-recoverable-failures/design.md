## Context

现有 `CollectorRuntime` 已有三级页面恢复、浏览器代际管理、持久检查点、幂等批次队列和脱敏诊断，但所有路径最终仍汇入顶层 `CollectionPausedError`：作者页三级恢复失败、推荐页恢复失败、同步批次累计三次失败或媒体上传抛错都会使远端运行进入 `paused`。2026-09-28 真机证据显示，同一作者的可见“服务异常”先后穿过重载、重建作者页和浏览器代际 2→3 的完整恢复仍存在，最终在 838 个作品、698 位作者、11 位候选处暂停；待同步批次为 0，证明暂停来自页面恢复预算而非数据积压。

本设计只改变已明确归类为无需人工处理的故障处置。验证码、登录失效、明确平台限制、设备撤销、协议拒绝和本地持久化失败继续 fail-closed。参见 proposal.md 与 `specs/douyin-local-collection/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让单个作者的永久暂时性错误只损失该作者本轮观察，不中断整场运行。
- 让推荐流、中心服务和 OSS 的暂时性故障以低频、可取消、资源有界的方式持续等待恢复。
- 保持检查点、进度、批次、截图和幂等键在跳过或重试前先安全落盘。
- 在控制页清楚区分“跳过并继续”“冷却重试”和“必须人工处理”。

**Non-Goals:**

- 不保证验证码、登录失效、平台限制、设备撤销、磁盘故障、进程退出、电脑休眠或人工关闭浏览器后仍无人值守运行。
- 不自动点击“重新刷新拉取数据”、验证码或任何互动控件，不切换账号或画像，不提高请求频率。
- 不为跳过的作者创建占位观察、失败候选或伪造字段，也不改变服务端协议和数据库结构。

## Decisions

### D1: 用“故障作用域”决定跳过还是等待，不再用统一恢复预算决定暂停

作者页故障只影响当前推荐项，因此三级恢复全部失败后返回一个明确的 `skipped_transient` 结果，而不是抛出暂停异常。采集循环在保存检查点后把该作品标识和作者主页加入本轮去重集合，递增已浏览作品、已核验作者和独立的可恢复故障跳过计数，然后继续。跳过不生成观察、批次、截图或硬筛结果；缺失数据保持未知。

推荐流是继续发现的共享入口，不能跳过，因此完整恢复阶梯失败后进入冷却周期，再开启下一恢复周期。退避间隔指数增长并设置上限；每周期最多一个浏览器上下文、一个推荐页和一个作者页。原“一小时第三次上下文恢复即暂停”的熔断改为“一小时达到阈值后进入最长冷却”，只针对明确的 `transient_page_failure`；安全事件仍在每次请求后重新检查并立即暂停。

备选方案是所有暂时性故障都无限重试同一对象，但这会让单个坏作者永久阻塞进度；另一方案是第一次错误即跳过，虽然连续性高但会放弃已有的低频自愈能力。

### D2: 用判别结果表达作者核验，而不是以异常同时表达控制流和安全事件

作者核验恢复入口返回“可信观察”或“暂时性跳过”的判别结果。只有登录、验证码、明确平台限制、无法分类和本地安全故障继续抛出暂停异常。这样采集循环可以在公开边界上测试“永久服务异常后继续下一作者”，且不会把普通跳过误记为错误暂停。

检查点新增向后兼容的可选 `recoverableSkips` 摘要：累计次数、最近页面类型、固定原因代码和发生时间。旧检查点归一化为 0；日志新增固定结果 `skipped` / `cooling`，不保存正文或完整地址。控制页用摘要展示累计跳过数和当前冷却时间。

### D3: 同步与媒体暂时失败复用持久数据和可取消退避

批次队列继续作为结构化数据的持久事实来源。移除“attemptCount >= 3 即暂停”的运行时分支，改为读取队列 `nextAttemptAt` 并通过可取消等待休眠；等待期间不翻页，人工暂停/终止仍生效。网络异常、超时和 HTTP 5xx 可重试；401/403、426、业务批次 `rejected` 等明确拒绝立即暂停。

媒体截图继续保存在检查点，上传成功前不清空 `pendingBatch` 或 `screenshot`。上传错误需要携带可判定类别：网络/超时/5xx 为暂时性并进入同一退避，未配对、无效签名地址、明确 4xx 或关联拒绝为人工事件。现有批次幂等键保证上传恢复前重复发送结构化批次不会产生重复业务记录。

备选方案是为媒体另建磁盘队列表，但当前检查点已经原子保存单张待传截图；新增第二套队列会扩大迁移和一致性范围。

### D4: 本地持久化是继续运行的硬闸门

每次作者跳过、重试状态变化、批次排队和截图保留都必须先成功保存检查点或队列记录。EPERM/EACCES/EBUSY 继续执行现有短时文件锁重试；最终失败、磁盘满、损坏 JSON 或权限错误不得进入无限重试并继续采集，因为此时无法证明数据安全。该类错误记录脱敏诊断后暂停。

### D5: 运行级公开接口作为回归测试缝

测试通过 `CollectorRuntime.start()`、`status()` 和远端 API 端口观察行为，不直接调用私有恢复方法。第一条红灯固定复现“同一作者在重载、重建页、重启浏览器后仍显示服务异常”，断言当前代码会调用远端 pause；目标断言改为不 pause、累计一次跳过并处理下一作者直至服务端停止条件。随后按垂直切片补推荐流跨冷却恢复、同步/媒体暂时失败恢复，以及验证码和本地写盘失败仍暂停。

## Risks / Trade-offs

- [暂时性分类错误可能让本应人工检查的页面被跳过] → 每次恢复后重新执行安全分类，登录、验证码、401/403/429、访问频繁和账号异常优先于暂时性文案；无法分类仍暂停。
- [跳过作者降低本轮召回率] → 只在完整低频恢复失败后跳过，记录累计数和固定原因；不伪造失败结论，后续运行仍可重新遇到该作者。
- [持续重试可能长期占用电脑] → 间隔指数增长并封顶，资源数量有界，停止条件时间继续累计，人工暂停/终止始终可取消等待。
- [中心服务长期不可达时无法得知服务端已暂停/终止或达到停止条件] → 断网期间停止翻页，只保留本地待同步数据并重试；恢复连接后先同步运行状态和停止条件，再继续浏览。
- [同一检查点中的截图可能导致结构化批次重复发送] → 依赖既有幂等键和 duplicate acknowledgement；只有批次与证据均确认后才清空检查点。

## Migration Plan

1. 先用现有运行级 harness 增加永久作者服务异常的红灯测试，锁定“不暂停、跳过并继续”的公开行为；再逐个实现作者结果类型、检查点摘要和控制页展示。
2. 将推荐流熔断改为有界冷却循环，并增加人工取消、停止条件、验证码优先级和资源上限测试。
3. 将批次、中心 API 和媒体暂时失败接入可取消退避；保持明确拒绝和本地持久化失败暂停，运行相关定向测试。
4. 同步文档和版本说明，修复现有 TypeScript 测试空值错误，运行 `npm run check`、MySQL/E2E（按改动风险）、OpenSpec 严格校验和 Windows 包级冒烟。
5. 构建新 Windows 版本到同级新目录，确认共享 `../data` 的检查点、DPAPI 令牌和画像可复用；暂停旧进程并在待同步为 0 后切换。保留当前 v0.1.10 目录和 ZIP 以便回退。
6. 小范围真实运行核对：永久异常作者产生一次跳过并继续、队列无积压、最终只由任务停止条件或安全事件结束。macOS 仅同步源码和文档，双架构真机门禁完成前不宣称新版可用。

回滚时暂停新版本并等待可同步数据清空，再启动保留的旧目录。新检查点字段均为可选，旧版本忽略未知字段；不删除共享 `data`。旧版本会恢复“暂时性故障预算耗尽后暂停”的行为，回滚说明必须明确这一差异。
