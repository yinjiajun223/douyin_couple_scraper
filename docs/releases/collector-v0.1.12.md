# Collector v0.1.12

## 变更摘要

- 修复作者页暂时故障触发同画像浏览器重启后，运行仍在旧推荐页等待并被误判为 `BROWSER_CLOSED` 的问题。
- 作者故障跳过和低可信度跳过现在都只在当前浏览器代的推荐页等待，随后继续发现；真正缺少或关闭当前推荐页时仍安全暂停。
- 保留 v0.1.11 的恢复、冷却、持久批次与媒体重试行为，采集协议仍为 `1.0.0`，服务端最低采集器版本不提高。

## 验证状态

- 自动化回归会模拟真实 Chrome：浏览器上下文关闭后，旧页面的 `waitForTimeout` 抛出 `BROWSER_CLOSED`；修复后运行继续同步下一位可信作者并达到停止条件。
- Windows 正式 ZIP 已生成：`artifacts/collector-windows-v0.1.12.zip`，44,303,544 字节；包级冒烟和 `start-collector.cmd` 启动器冒烟通过，内置 Node、DPAPI 配对往返、独立画像、可见 Chrome、本机控制服务和公开 CA 均通过检查。
- SHA256：`7745aa66de71e9600ade06a76da75a56204b9f3c05a47070cc6703b6ba0e2ad5`；与同目录 `.sha256` 文件一致。
- 2026-09-29 完成 Windows 小范围真实运行验收：运行最终由配置停止条件正常结束，服务端与本机检查点均为 4,441 个浏览作品、3,003 位核验作者和 49 位硬筛通过；累计 31 次解析跳过、133 次可恢复故障跳过，期间未再因旧页面 `BROWSER_CLOSED` 中断。
- 完成时待同步批次与截图均为空，控制页、服务端进度和检查点一致；恢复诊断保持 3 个有界日志文件，敏感模式扫描为 0。`recovery.jsonl` 中的 `skipped` 表示恢复状态迁移事件，唯一作者跳过计数以检查点和控制页的 `recoverableSkips` 摘要为准。
- Windows v0.1.12 初次线上验证通过，可继续受控使用并观察长期运行；这不替代后续版本升级、真实 OSS 或平台页面变化后的回归验收。
- macOS 只同步共享源码和版本；未构建通用包，也未完成 Apple Silicon/Intel 双架构真机门禁。

## 安装与回退

先人工暂停旧运行并确认待同步数据状态，关闭旧助手和其可见 Chrome。将 v0.1.12 解压到旧版本同级的新目录，继续复用 `../data`，不要覆盖旧目录或复制 DPAPI/Keychain 令牌。验证完成前保留 v0.1.11 和更早目录；需要回退时先关闭 v0.1.12，再从旧目录启动并人工继续。
