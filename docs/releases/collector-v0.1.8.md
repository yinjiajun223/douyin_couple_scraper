# 采集助手 v0.1.8 验证误判修复

## 已确认的问题

旧判定对 URL、标题和整页正文做验证关键词子串匹配。普通作品文案“不要把验证码告诉陌生人”“汽车安全验证测试记录”等也会触发 `captcha_required`。修复前通过纯判断函数和完整作者核验入口复现，新增的 4 项回归均失败。

该缺陷可以稳定复现，但用户之前那次真实暂停未保留触发依据，因此不能声称已还原那次暂停的确切原因，也不能据此认定抖音没有短暂验证状态。

## 修复范围

- 不再把整页正文、作品标题、作者标识或 URL 查询参数中的验证词直接当成验证码。
- 验证地址按实际路径段识别；页面检查区分可见验证弹窗、验证控件/框架，以及普通内容区域外的明确验证提示。
- 判断可见性时检查祖先隐藏/透明状态及文本和元素是否位于视口内。普通作品卡片和作者资料中的引用文案不作为独立验证提示。
- 真实验证仍立即暂停，不点击、填写或绕过验证码，也不新增刷新重试。安全状态读取失败不当作正常继续。
- 安全暂停也写入原有脱敏诊断历史：保留推荐页/作者页、时间、运行 ID 和固定的触发依据代码。继续或重启不清空，控制页显示中文依据。
- 不记录页面正文、完整地址、Cookie、令牌、验证码或原始 DOM，不上传诊断。既有容量轮换规则不变。

## 验证

- `npm run check` 通过，含采集器 95 项测试。
- `node scripts/test-collector-safety-dom.mjs` 通过：隔离 Chrome 中 20 项 DOM 场景和 2 项真实作者核验调用场景。普通文案/隐藏验证不暂停，可见验证仍抛出安全错误。
- 覆盖作者页与推荐页安全暂停记录、恢复后历史保留、重启后重新读取，以及无法读取验证控件时不启动采集。
- UTF-8 与 `git diff --check` 通过。
- Windows 包级冒烟通过：内置 Node、DPAPI 配对往返、独立画像、可见 Chrome 和本机控制服务均正常。已安装目录再执行原误判输入，普通文案不暂停，可见验证信号仍暂停。
- 没有进行新版真实抖音采集验收。用户取消的两小时/24 小时真实试跑和回退演练没有执行，不记作通过；没有运行占用固定 43127 端口的启动器测试，也未中断当前运营助手。
