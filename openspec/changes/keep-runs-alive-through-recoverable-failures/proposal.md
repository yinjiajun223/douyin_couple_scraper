## Why

真实 Windows 长运行已经证明，单个作者页持续显示“服务异常”时，即使刷新、重建作者页和重启浏览器全部执行，现有恢复预算耗尽逻辑仍会暂停整场运行；瞬时文件锁和连续网络失败也可能产生同类中断。运营目标不是在所有外部状态下强行请求，而是让一次人工启动的运行在未达到任务停止条件前，对无需人工处理的故障保持连续：能跳过的当前对象安全跳过，不能跳过的共享入口低频等待并重试。

## What Changes

- 作者页可确认属于暂时性故障且三级恢复仍失败时，不再暂停整场运行；助手将该作者记为未取得可信观察、累计一次“可恢复故障跳过”，不写入作者、作品、候选或截图，然后继续下一条推荐内容。
- 推荐流、中心 API、OSS 或持久同步队列的暂时性失败不能通过跳过单个对象解决时，保持当前运行和本地数据，采用可取消、有上限间隔的低频重试循环，直到恢复、任务达到停止条件或运营人员人工暂停/终止。
- 保留必须人工介入的暂停边界：登录失效、验证码、安全验证、明确访问频繁/账号异常/平台限制、设备撤销，以及无法安全保存检查点或待同步数据的本地持久化故障仍立即暂停。
- 将恢复诊断区分为“已恢复”“已跳过并继续”“持续冷却重试”和“必须人工处理”，并保持日志、检查点、浏览器标签、内存集合和退避间隔有界。
- 补充运行级回归，覆盖作者页永久服务异常后继续下一作者、暂时性推荐流/同步失败跨多个重试周期后恢复、停止条件与人工暂停仍生效，以及验证码和持久化失败仍暂停。
- 同步 Windows/macOS 助手、产品手册和运营手册；重新构建 Windows 包并完成包级冒烟，现有 macOS 真机发布门禁不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `douyin-local-collection`: 将无需人工处理的暂时性故障从“恢复预算耗尽后暂停”调整为“作者级故障跳过并继续、共享入口故障持续低频重试”，同时保留安全事件和本地持久化失败的 fail-closed 边界。

## Impact

- 主要影响 `apps/collector/src/runtime.ts`、恢复检查点/诊断状态、持久同步队列调用方式、本机控制页文案及对应运行级测试。
- 不改变采集批次协议、服务端远程控制边界、硬筛规则或未知值语义；跳过的作者不会生成任何共享观察，也不会把缺失字段填成 0。
- 需要同步 `README.md`、`docs/product-manual.md`、`docs/operations/operator-guide.md`、`docs/collector-windows.md` 和 `docs/collector-macos.md`，并发布包含既有文件锁修复的新 Windows 包。
- 不增加验证码处理、自动互动、高频刷新、画像切换或规避平台限制的行为。
